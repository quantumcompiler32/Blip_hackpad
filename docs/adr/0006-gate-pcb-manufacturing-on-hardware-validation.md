# Gate PCB manufacturing on hardware validation

Blip’s PCB must not be submitted for manufacturing until its Hardware Validation Gate passes: display datasheets and addresses are verified, the Newhaven control pins have defined levels, voltages and pull-ups are correct, physical encoder identity and direction are established, KiCad ERC findings are resolved or justified, and schematic, layout, BOM, firmware pin map, and hardware documentation agree. The repository’s `PCB/` directory is the single source of truth for the active `.kicad_pro`, `.kicad_sch`, and `.kicad_pcb` files; automatic history, backups, locks, local preferences, and the unrelated Starter project are excluded. Codex may migrate, audit, and make evidence-backed corrections to those source files, then run ERC, DRC, and schematic parity. All required edits and evidence live in one Hardware Change Guide with an ordered checklist, annotated before/after visuals, exact KiCad operations, reasons, warning dispositions, pin mappings, verification results, and a final manufacturing checklist. A fresh `CAD/Blip-PCB-Assembly.step` export is required after corrections, but a full enclosure is a parallel enhancement and does not block initial PCB approval; mounting features and mechanical clearances are still audited now. A human must open the edited project and complete the guide’s final visual review before approval or manufacturing. This hardware track is prioritized for Hack Club approval and may proceed in parallel with simulator-first Foundation Release software because the simulator does not depend on fabricated hardware.
